# 难度与隐藏任务 V2 设计方案

## 目标

把当前的“难度 + 路线模式”合并成真正清晰的三档：

```text
轻松 / 标准 / 挑战
```

每一档不只是奖励倍率不同，而是同时影响：

- 今日动作内容
- 完成门槛
- 奖励池
- 隐藏任务触发
- 小基地建设节奏

隐藏任务也从“容易触发的小彩蛋”升级为一个更有用的系统：发现隐藏任务后可以解锁装饰、奖杯、建筑区域、真实礼物资格和瓶中信线索。

## 当前问题

### 难度选择太多

现在页面有两层选择：

```text
轻松 / 标准 / 挑战
恢复路线 / 建设路线 / 探险路线
```

用户理解成本高，而且两层选择的差异不够直观。实际使用时更像 6 种组合，但用户只需要知道“今天轻松点、正常做、还是挑战一下”。

### 难度内容差异不明显

当前主要是奖励倍率和提示文案不同，训练动作本身没有明显变化。用户选择挑战时，不会感觉今天真的更难；选择轻松时，也不会感觉系统主动帮她减负。

### 隐藏任务太容易

现有隐藏任务大多是一次性触发：

- 晚上打卡
- 双人同日
- 挑战完整完成
- 周复盘完成

它们适合做新手彩蛋，但长期目标不足。

### 隐藏奖励用途偏弱

部分隐藏奖励已经有用途，比如里数券看瓶中信、星星碎片点亮装饰、金色树叶登记奖杯。但整体还没有形成明确闭环：

```text
触发隐藏 -> 得到奖励 -> 解锁功能/装饰/奖杯/礼物 -> 推动小基地成长
```

## 难度设计

### 1. 轻松

定位：保连续，不制造压力。

适合场景：

- 今天累
- 时间不够
- 只想保留登岛记录
- 不想因为做不完而放弃

训练内容规则：

- 只保留低压力动作
- 优先保留热身、拉伸、放松、低强度激活
- 力量动作减量或跳过
- 今日动作数量控制在 2-3 个

示例：

```text
原计划：
原地踏步 3 分钟
深蹲 12 个 x 2
弓步蹲 每侧 8 个
平板支撑 20 秒 x 2
站立拉伸 每侧 20 秒

轻松版：
原地踏步 2 分钟
靠墙静蹲 15 秒
站立拉伸 每侧 20 秒
```

奖励：

```text
积分：动作数 x 1
材料：1-2 个
常见：树枝、杂草、贝壳
少量：木材
不掉落：铁矿石、铃钱袋
```

隐藏倾向：

- 连续轻松 3 次：金色树叶
- 休息后轻松回归：欢迎回岛记录
- 轻松但完整完成 5 次：小花路牌装饰

设计原因：

轻松不应该是“少奖励的惩罚”，而应该是“低压力保连续”。奖励少一些，但可以触发温柔型隐藏任务。

### 2. 标准

定位：默认训练和稳定建设。

适合场景：

- 正常训练日
- 不想做额外挑战
- 希望稳定推进岛屿建设

训练内容规则：

- 使用 `plan.json` 原动作
- 不加量，不减量
- 当前计划仍是标准版的来源

奖励：

```text
积分：动作数 x 2
材料：2-3 个
常见：木材、石头、软木材、硬木材
少量：贝壳、黏土
```

隐藏倾向：

- 标准完整完成 3 次：建设代表进度
- 双人同日标准完成：里数券
- 一周标准完成 4 天：仓库整理券

设计原因：

标准是小基地建设的主路线。它不追求稀有奖励，但最稳定地给建筑材料。

### 3. 挑战

定位：状态好时冲一次，换更稀有的奖励。

适合场景：

- 今天精神好
- 想多拿奖励
- 想推进隐藏任务、真实礼物和奖杯

训练内容规则：

- 基于标准版加量
- 热身和收尾不加量
- 核心、腿部、上身、后侧动作加一点
- 不建议把挑战变成很累，只做“小幅上调”

加量规则建议：

```text
带“秒”的动作：+5 到 +10 秒
带“个”的动作：+2 到 +5 个
带“组”的动作：+1 组，或每组少量增加
收尾/拉伸/放松：保持不变
```

示例：

```text
标准：
深蹲 12 个 x 2
平板支撑 20 秒 x 2
猫牛式 10 次

挑战：
深蹲 15 个 x 2
平板支撑 25 秒 x 2
猫牛式 10 次
```

奖励：

```text
积分：动作数 x 3
材料：3-4 个
常见：木材、石头、硬木材
稀有：铁矿石、黏土、铃钱、里数券
完整完成概率触发：铃钱袋
```

隐藏倾向：

- 挑战完整完成 1 次：铃钱袋
- 挑战完整完成 3 次：任选心愿一次资格
- 两人同日挑战：秘密码头包裹
- 夜间挑战完整完成：星星碎片 + 观星台线索

设计原因：

挑战必须给用户明确反馈：今天内容确实更难，奖励也确实更好。否则挑战只会变成一个倍率按钮。

## 页面调整

### 删除第二排路线模式

删除：

```text
恢复路线 / 建设路线 / 探险路线
```

只保留：

```text
轻松 / 标准 / 挑战
```

### 难度卡片显示内容

难度卡片建议显示：

```text
今日难度
[轻松] [标准] [挑战]

今日内容：3 个动作 · 轻量版
奖励预览：树枝 x1 · 贝壳 x1 · 4 积分
隐藏线索：连续轻松几天，树叶可能会变成金色。
```

### 导航栏图标优化

当前底部导航使用 emoji，视觉不够像 NookPhone，也和页面里的动森素材风格不统一。V2 实施时需要把底部导航改成本地图片图标。

目标：

```text
今日 / 岛屿 / 背包 / 图鉴 / 礼物 / 贡献
```

图标建议：

```text
今日：NookPhone / Nook Miles 类图标，表达每日任务
岛屿：Map 类图标，表达岛屿地图
背包：DIY / pocket / item 类图标，表达物品
图鉴：Critterpedia 类图标，表达收藏册
礼物：Nook Shopping / present 类图标，表达礼物码头
贡献：Passport / bulletin / achievement 类图标，表达周贡献
```

资源优先级：

```text
1. Nintendo 官方 Animal Crossing: New Horizons 页面中可直接访问的小图标
2. Play Nintendo 官方页面中的 Animal Crossing 素材
3. Nookipedia 的 NookPhone / New Horizons icons 分类
4. Fandom 的 New Horizons icons 分类
5. 如果以上不够，再用本地原创森系图标兜底
```

已确认可参考来源：

```text
Nintendo official ACNH site
https://animalcrossing.nintendo.com/new-horizons/

Nookipedia NookPhone
https://nookipedia.com/wiki/NookPhone

Nookipedia New Horizons sprites
https://nookipedia.com/wiki/Category:New_Horizons_sprites

Fandom New Horizons icons
https://animalcrossing.fandom.com/wiki/Category:Icons_(New_Horizons)
```

落地规则：

- 图标下载到 `src/assets/nav-icons/`。
- 每个图标在 `src/assets/nav-icons/SOURCES.md` 记录来源 URL。
- 底部导航不再直接使用 emoji。
- 图标尺寸统一，例如 40x40 或 48x48。
- 保留文字标签，避免只靠图标导致误解。
- 这是私人网页可使用官方风格资源；如果未来公开发布，需要替换为原创图标。

### 动作列表展示

动作列表直接展示当前难度生成后的动作。

如果是轻松或挑战，需要有轻量提示，但不要显示太多解释：

```text
轻松版
原地踏步 2 分钟

挑战版
深蹲 15 个 x 2
```

### 历史详情

历史日详情继续显示：

```text
难度：轻松 / 标准 / 挑战
动作：显示当天实际难度下的动作内容
奖励：显示实际获得的奖励
隐藏：显示触发的隐藏任务
```

旧数据里如果有 `planMode`，历史详情可以不再展示，或者显示在备注里：

```text
旧路线：建设路线
```

## 数据设计

### 保留字段

继续保留：

```js
dayState.difficulty
selectedDifficulty
```

### 弱化字段

逐步废弃：

```js
dayState.planMode
selectedPlanMode
```

兼容策略：

- 旧存档导入时不报错。
- 旧记录里有 `planMode` 时可以保留，但新结算不再写入。
- 同步记录可以暂时保留 `selectedPlanMode`，避免旧页面读不到字段，但新版 UI 不显示。

### 新增运行时生成函数

不改 `plan.json` 结构，新增前端生成函数：

```js
getDifficultyDay(day, difficulty)
```

返回值：

```js
{
  exercises: [],
  summary,
  rewardProfile,
  variantLabel
}
```

这样 `plan.json` 仍然只维护标准训练计划，轻松版和挑战版由前端自动生成。

## 动作生成规则

### 轻松版生成

输入：标准动作列表。

保留优先级：

```text
1. 热身入口
2. 收尾 / 拉伸 / 放松
3. 低强度激活
4. 核心或力量动作中最温和的一项
```

最多保留 3 个动作。

动作文字调整：

```text
3 分钟 -> 2 分钟
12 个 x 2 -> 8 个
20 秒 x 2 -> 15 秒
```

### 标准版生成

直接返回原动作。

### 挑战版生成

输入：标准动作列表。

调整规则：

```text
热身：不变或 +1 分钟
收尾/拉伸/放松：不变
核心/腿部/上身/后侧：小幅加量
```

加量文本只改展示，不需要复杂解析所有单位。第一版可以用规则表处理常见表达：

```text
8 个 -> 10 个
10 个 -> 12 个
12 个 -> 15 个
15 秒 -> 20 秒
20 秒 -> 25 秒
25 秒 -> 30 秒
```

遇到无法识别的文本，追加：

```text
挑战：多 1 组或多 2 次
```

## 隐藏任务 V2

隐藏任务分三层：

```text
普通隐藏
稀有隐藏
传说隐藏
```

### 普通隐藏

用途：给新手反馈，触发简单，主要进图鉴。

示例：

```text
夜海星光
条件：20:00 后或 05:00 前完成
奖励：星星碎片
用途：解锁星星地砖

同日登岛
条件：两个人同一天都完成
奖励：里数券
用途：瓶中信额外线索

金色树叶
条件：轻松完整完成累计 3 次
奖励：金色树叶
用途：登记金叶奖杯
```

### 稀有隐藏

用途：推动小基地和真实礼物。

示例：

```text
稳定建设
条件：标准完整完成累计 5 次
奖励：仓库整理券
用途：直接给共同仓库补 3 份木材

挑战岛民
条件：挑战完整完成累计 3 次
奖励：任选心愿一次资格
用途：解锁真实礼物“任选心愿一次”

双人建设日
条件：两个人同一天都选择标准并完整完成
奖励：合作木牌
用途：岛屿装饰
```

### 传说隐藏

用途：长期目标，不直接告诉答案，只给线索。

示例：

```text
观星台许可
线索：夜里完成探险路线，星星会记住你。
真实条件：夜间挑战完整完成 2 次
奖励：观星台点位
用途：岛屿新增装饰/建筑点

秘密码头包裹
线索：两位岛民同一天走得更远，码头会靠岸。
真实条件：两个人同日挑战完整完成
奖励：秘密码头包裹
用途：解锁真实礼物高级兑换

金色岛民证
线索：轻轻地来，也一直来。
真实条件：轻松完整完成 7 次
奖励：金色岛民证
用途：头像框 / 博物馆奖杯
```

## 本周结算规则

当前“周结算仪式”按钮需要收紧，避免周中提前结算。

规则：

```text
只有周日当天可以点击本周结算
并且周日当天必须已经处理完成
```

“周日当天已处理完成”包括：

```text
1. 周日完成打卡
2. 周日选择今天休息
```

不允许：

```text
周一到周六提前结算
周日还没打卡/没休息时结算
未来周日提前点击
```

按钮状态：

```text
周一到周六：按钮禁用，文案“周日完成后结算”
周日未处理：按钮禁用，文案“先完成今天”
周日已处理：按钮启用，文案“生成本周结算”
已生成本周结算：按钮禁用，文案“本周已结算”
```

结算内容：

```text
本周合计登岛次数
本周双人同日次数
共同仓库材料数
本周最稳日
本周最弱动作类
下周建议
```

这样周结算和周复盘一致，都必须等一周结束后才生成，避免数据不完整。

## 触发规则

隐藏任务触发时间：

```text
结算当天时触发
同步到对方数据后可回溯补发同日类隐藏
使用物品时可触发物品类隐藏
节日日期可触发节日隐藏
```

避免重复触发：

```text
每个隐藏任务 ID 只进入一次 collection
可累计型任务单独记录进度，不重复发同一个发现奖励
```

## 验收标准

### 难度

- 页面只显示三个难度按钮。
- 不再显示第二排路线模式按钮。
- 选择轻松时，动作数量减少或强度降低。
- 选择标准时，动作与 `plan.json` 一致。
- 选择挑战时，动作有明显但不过度的加量。
- 三档奖励预览不同。
- 三档结算奖励不同。

### 隐藏

- 隐藏任务分为普通、稀有、传说。
- 未发现隐藏仍显示 `???`。
- 已发现隐藏能查看用途。
- 至少一个隐藏奖励能解锁装饰。
- 至少一个隐藏奖励能影响真实礼物。
- 里数券能继续用于瓶中信线索。

### 导航

- 底部导航不再使用 emoji 作为主图标。
- 导航图标来自本地 `assets/nav-icons/`。
- 图标来源记录到 `SOURCES.md`。
- 六个导航入口在移动端不溢出。

### 周结算

- 周一到周六不能生成本周结算。
- 周日未打卡/未休息时不能生成本周结算。
- 周日完成或休息后可以生成本周结算。
- 已生成后不能重复生成同一周结算。

### 兼容

- 旧记录可以继续显示。
- 旧存档导入不报错。
- 不再使用 localStorage 作为权威数据。
- 服务端同步结构不需要大改。

## 推荐结论

采用“三档即三路线”的方案：

```text
轻松 = 低压力保连续
标准 = 稳定建设小基地
挑战 = 稀有奖励和隐藏任务
```

这是最适合当前项目的方案，因为它让用户只做一个选择，却能同时改变训练内容、奖励和隐藏任务方向。
